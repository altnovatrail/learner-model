# CLAUDE.md — working rules for this repository

If `spec/RULES.md` does not exist, the `spec` submodule is not checked out and the rules imported below are missing: stop before any work and ask the author to run `git submodule update --init`.

## Your role

You are the architect of `learner-model`, a component of NovaTrail: the library that estimates how well a learner has mastered each skill from the evidence of attempts and computes each skill's state, with no input or output of its own. It does not pick the next lesson or task, which is the engine's, gives no verdict, never calls an AI model and never reads a module package or a database. The documents under `docs/`, but for the epic archives `docs/plan/`, are written for the session of Claude Code that changes the component: write them so that it can act on them without asking what you meant. The bar they meet, and which texts are written for people instead, are in the shared rules below.

## The component

It is a library inside `api`, the one service of the first slice: when an attempt ends, `api` hands it the evidence and the skill graph, and then `engine` picks what comes next (architecture 2 spec, architecture 3.5 spec, R15 spec). It computes without input or output — the time comes from outside, and it takes no seed — on Go's standard library alone, with its own graph types, and gives the same bits on every build, WebAssembly included (architecture 3.8 spec; R09); it encodes evidence and state in protobuf's binary form by a schema of its own (R10). It stores nothing: `api` keeps the learner's append-only evidence log, the source of truth, and the skills' state as a cache marked with the version of learner-model, the release of modules and `api`'s window of format versions; the state is a fold of the log, so an appended record gives the state recomputed from the log bit for bit, and a retired skill's evidence counts in full for each skill that replaced it (R08; R80 spec and its fourth amendment; privacy 4 spec). Its model is standalone's — a Rasch model with a guessing floor, Elo-style updates, a trial series and a cautious "mastered" — with the level kept for each module (R03), forgetting as each skill's retention and, after a pause of the module, of its level (R04), evidence weighed by outcome, key provenance and series (R06), and an anchor skill of the shared taxonomy read from the mastered skills that teach it (R07; concepts 11 spec). It belongs to stage 1 with `engine` and `sim`, and `engine`, `sim` and `api` are built with it (repositories 2.1 spec, repositories 3 spec); every change after its first version passes the gate of `sim`, and a change of what the model computes goes through `sim`'s judgement before it is released (R12, R20; R103 spec). Where the work stands — the epics done, the current one and what comes next — is in [RUN.md](RUN.md).

Its card in spec is architecture 3.8 spec. The card is the summary and this repository's [docs/architecture.md](docs/architecture.md) is the detail: section 2 there lists what the card left to decide, decided, with what was deliberately deferred; section 3 is how it is built.

## Environment

Open the repository in VS Code and choose "Reopen in Container"; clone it with `--recurse-submodules`, or the container checks out `spec/` when it starts. Keep the clone in a folder named `learner-model`, as `git clone` names it: `.claude/settings.json` keeps spec's own CLAUDE.md and its rules, `spec/.claude/rules/`, out of this repository's sessions by that path. The container is spec's: Node.js, Go, buf and just, and the GitHub CLI and Claude Code on top. The tools of this repository's own code come with that code, at exact versions; how its container then differs from spec's is recorded as a decision, as R46 canvas-api did for canvas-api — none so far (R19).

- `just -f spec/justfile docs-check-repo` checks its documents: that its links lead somewhere, that every section and number it cites — its own and spec's, against spec/ at its tag — exists, that the decision log runs without gaps, and the tables of its RUN.md and DEBT.md (R32 spec), and that its files, rules, decision entries, sections and rows keep within their budgets of size: spec's block `repository` of `spec/tools/docs-check/budgets.json`, with what [docs-budgets.json](docs-budgets.json) names in its place — raising one is an edit of that file (R145 spec). A task that touches them ends with it green; on a tag of spec older than the check, the same is checked by hand.
- `.claude/settings.json` compacts a session at 400 thousand tokens, fetches no claude.ai connector, runs the hook of one task per session from `spec/tools/session/` and turns on the plugin `gopls-lsp`, for gopls's diagnostics after an edit of Go code; the plugin loads only in a folder Claude Code trusts (R143 spec; R35).
- **The checks of each part** are its rule, `.claude/rules/<part>.md`, with the part's files in its `paths`: Claude Code loads a rule only when the session reads or edits a file it matches, and drops it at compaction, and CI runs every check on every pull request (R143 spec; measurements 1.5 spec). Before changing a part, read its rule. The rules and their parts: [go](.claude/rules/go.md) — the Go code, `go.mod`, `testdata/` and the lists of the rules of code; [proto](.claude/rules/proto.md) — the schema of the evidence and the state, `proto/` and `buf.yaml`, and the golden bytes of the codec; [ci](.claude/rules/ci.md) — CI, the gate, the release and the container: `.github/`, `.devcontainer/`, `.claude/settings.json` and the `justfile`.
