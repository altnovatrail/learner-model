# CLAUDE.md — working rules for this repository

If `spec/RULES.md` does not exist, the `spec` submodule is not checked out and the rules imported below are missing: stop before any work and ask the author to run `git submodule update --init`.

## Your role

You are the architect of `learner-model`, a component of NovaTrail: the library that estimates how well a learner has mastered each skill from the evidence of attempts and computes each skill's state, with no input or output of its own. It does not pick the next lesson or task, which is the engine's, gives no verdict, never calls an AI model and never reads a module package or a database. Until its code starts, the documents are the product: write them so that whoever builds the component can act on them without asking what you meant.

## The component

It is a library inside `api`, the one service of the first slice: when an attempt ends, `api` hands it the evidence and the skill graph, and then `engine` picks what comes next (architecture 2 spec, architecture 3.5 spec, R15 spec). It computes without input or output: the time comes from outside and it takes no seed, needing no randomness (R09), and its graph types are its own, not module-kit's, and it gives the same bits on every build, WebAssembly included, so that it could also be built for the device, though Т-10 recommends computing on the server (architecture 3.8 spec, repositories 1 spec, R09); it encodes evidence and state in protobuf's binary form by a schema of its own (R10). It stores nothing: the learner model is a learner's data, and it lives in `api`'s database as an append-only evidence log, the source of truth, with the skills' state as a cache marked with the version of learner-model, the release of modules and `api`'s window of format versions. What an evidence record holds and how much it weighs is this library's to decide, and `api` keeps it as it is; the one condition is that the state an appended record gives equals the state recomputed from the log (R80 spec, which closed П-7 and Т-22, and its fourth amendment, which added the window; privacy 4 spec). An evidence record carries every observation that recompute reads, in a form that only grows; the state is a fold of the log, so appending gives the recomputed state bit for bit on any build; and a retired skill's evidence counts in full for each skill that replaced it (R08). It depends on nothing but spec, its code on nothing but Go's standard library (R09), and engine and api are built with it (repositories 2.1 spec, repositories 3 spec). Every change to it after its first version passes sim, which imports it with engine, by a criterion written before the first candidate; it belongs to stage 1 and comes with engine and sim, since the simulator needs both the model and the rule of choice (repositories 4 spec, repositories 6 spec, R103 spec). In spec's cross-repository plan, COORDINATION.md, its detailing needed only the move to spec's line 0.6, and this repository has done it, as the first epic of RUN.md; its code is the second epic, E2: its first version, checked by its own tests and standalone's test vectors, is the baseline the stand is built on, written and released signed before sim's first tag, as R103 spec decided — row 4.6 of COORDINATION.md (R76 spec), with every change after it through the gate, row 4.8 (R12), and the first candidates through sim's judgement, row 4.9 (R22, R23). The third epic, E3, takes the first candidates of the model to sim's judgement: up to three, each a draft pull request on the numbers that are still guesses, chosen by rough runs of the stand, and the one sim chooses released by the order of R103 spec (R22). Its starting point is standalone's model — a Rasch model with a guessing floor, Elo-style updates, a trial series and a cautious "mastered" — with the level kept for each module (R03), with forgetting added as each skill's retention, whose stability grows with spaced practice (R04), and with evidence weighed by outcome, key provenance and series (R06; concepts 11 spec, repositories 7 spec). Whether a learner has an anchor skill of the shared taxonomy it reads, at read time, from the mastered skills that teach it (R07).

Its card in spec is architecture 3.8 spec. The card is the summary and this repository's [docs/architecture.md](docs/architecture.md) is the detail: section 2 there lists what the card left to decide, decided by the first epic of [RUN.md](RUN.md), with what was deferred, one question that came later with О-25, decided with spec v0.9.5, and one that came with spec v0.9.16, how much format 0.4's leading question weighs, decided by the author: as help, in a field of its own (R21); section 3 is what to build.

## Environment

Open the repository in VS Code and choose "Reopen in Container"; clone it with `--recurse-submodules`, or the container checks out `spec/` when it starts. Keep the clone in a folder named `learner-model`, as `git clone` names it: `.claude/settings.json` keeps spec's own CLAUDE.md out of this repository's sessions by that path. The container is spec's: Node.js, Go, buf and just, and the GitHub CLI and Claude Code on top. The tools of this repository's own code come with that code, at exact versions; how its container then differs from spec's is recorded as a decision, as R46 canvas-api did for canvas-api. None so far: gopls, at an exact version and built from its lock file in `.devcontainer/gopls/`, which this repository once added itself (R14), now comes with spec's template for every Go repository (R19); the checks run from the `justfile` (R13), and those that hold the same bits on every build — the tests on the targets, the comparison of the assembler and the rules of code — as jobs of .github's shared Go workflow, with this repository's lists in `.github/coderules.json` (R18), and the gate of sim as a job of its own, Gate, which builds sim at the tag and commit it names on the code of each pull request and each commit of main (R20). `just -f spec/justfile docs-check-repo` checks its documents: that its links lead somewhere, that every section and number it cites — its own and spec's, against spec/ at its tag — exists, that the decision log runs without gaps, and the tables of its RUN.md (R32 spec). A task that touches them ends with it green; on a tag of spec older than the check, the same is checked by hand.
